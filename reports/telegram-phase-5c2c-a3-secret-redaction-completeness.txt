Root Cause: Sanitizer regex TELEGRAM_BOT_TOKEN\s*=\s*[\w-]{8,} used \w- which does NOT include colon (:). When applied to TELEGRAM_BOT_TOKEN=123456789:ABCdef_GHIjkl-MnopQRST, [\w-]{8,} matched only 123456789 (stopped at colon). Result: TELEGRAM_BOT_TOKEN=[REDACTED]:ABCdef_GHIjkl-MnopQRST — token leaked! Same issue affected MINIMAX_API_KEY, API_KEY, Bearer regexes if values contained colons. Additionally, CQA_CONTROL_TOKEN and standalone Telegram bot tokens were not in sanitizer at all.

What Changed:
- telegram-digest-sanitizer.ts: Changed [\w-]{8,} to [\w-:]+ for all key/token regexes. Added CQA_CONTROL_TOKEN rule and standalone Telegram bot token rule (\b\d+:[A-Za-z0-9_-]{35,}\b). Updated FORBIDDEN_PATTERNS.
- validate-sanitizer-secret-completeness.ts: NEW script with 36 tests.
- package.json: Added validate:sanitizer-secret-completeness script.
