## 3. APPROVAL_STATE

The state machine has 6 transitions:
1. `not_requested` (initial)
2. `approval_pack_ready` (current; 8/8 evidence met)
3. `human_review_pending` (future; requires human-approver UI)
4. `approved_for_future_promote` (future; requires env gate + audit)
5. `rejected` (future; human-rejected state)
6. `expired` (future; approval pack aged out)

After C5N1's smoke test, the planner reports `approval_state=approval_pack_ready` because all 8 pack-ready evidence items are met (latest sandbox run, output validation, diff, readiness, gate, shadow copy, rollback manifest, approval pack). The `allowed_next_transitions` is `["human_review_pending"]`, which is blocked in this phase (no human-approver UI).

## 4. HUMAN_APPROVAL_MODEL

The model uses 3 evidence checklists (one per transition level):

| Level | Items met (now) | Items needed |
|---|---|---|
| `approval_pack_ready` | 8/8 ✅ | — (all met) |
| `human_review_pending` | 0/3 (future) | human review, target files confirm, backup retention confirm |
| `approved_for_future_promote` | 0/3 (future) | human approval recorded, env gate set, audit log witness |

The `human_approval` field is never set to `true` in C5N1. Even when `approval_state=approved_for_future_promote` in a future phase, `production_write_allowed` remains `false` — the actual write is gated by the C5M1 controlled promote executor (token + phrase + env gate).
